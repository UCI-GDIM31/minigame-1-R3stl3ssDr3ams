# minigame-1
## Devlog
While perhaps unsurprinsing,considering their related nature as forms of art, building a game is very similar to organizing a stageplay. Like in theater, every game needs a
stage, or rather a scene, to set the environment for play, and developers must decide the kinds of ways they want their players to interact with that environment. It is essentially
an open space for the developer to build whatever experience they desire, but as expected, a director can't run a play with just an empty stage, and a developer can't publish a
game with a blank scene. Therefore, developers need their own version of actors, props, and sets, in order to create their inteded experience. This comes in the form of GameObjects,
which can represent anything from player avatars, to the objects they enage with, to the very scenery that they exist in. If a developer, for instance, wanted to build suspense
and tension within their game, they'd want to create smaller environments with limited resource availability. With this in mind, they would use whatever assets they have available
and add them into the scene, hence making them active GameObjects, in order to create a setting in which players navigate tight corridors, searching between cramped rooms to find
resources few and far between. Yet even GameObjects need scripts to tell them how to interact with each other, hence the use of components. Components dictate the properties each
GameObject has within a scene, whether or not it has collision, whether it counts as a healing item or a weapon, etc. A play with no script will reveal itself to be messy and 
unforcused, actors may be given props but they will have no sense of how to use it, nor will they know in what ways they are intended to interact with their environment;
a game without components can be just as catastrophic, if not worse. Without components, the program would have no way of understanding how GameObjects are meant to interact with
each other, what is meant to trigger and at what time. In stageplay, the fantasy can only exist once all aspects are working in tandem, a stage must be set, actors at the 
ready with scripts memorized; designing a game is just as complex and similarly artistic in nature, as the developer must balance everything from scenes, to GameObjects, to
their specific components, in order to create the best possible user experience.
